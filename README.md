# Telegram-бот для сохранения файлов на Яндекс.Диск

Бот сохраняет отправленные и пересланные фото, видео и документы на Яндекс.Диск.
Доступ разрешён только пользователям из `ALLOWED_IDS`; сообщения остальных пользователей
игнорируются без ответа. Проверяется ID отправителя сообщения боту, а не автора пересланного файла.

Фото сохраняются в наибольшем размере, доступном в сообщении Telegram.
Для сохранения оригинала передавайте исходный файл как документ.

## Качество фотографий, включая iPhone

Бот не меняет пиксели, формат и метаданные скачанного файла: передаёт на Яндекс.Диск
те же байты, которые вернул Telegram. Для фото выбирается версия с наибольшим
разрешением среди доступных в сообщении; при одинаковом разрешении — больший файл.

| Способ отправки в Telegram | Что сохранится на Диске |
| --- | --- |
| Обычное фото | Версия, которую Telegram уже сжал и мог уменьшить |
| Фото в режиме HD | Версия повышенного качества из Telegram; это тоже не оригинал |
| Исходный файл как документ | Полученный файл целиком, без перекодирования ботом |
| Пересылка ранее отправленного фото | Доступная версия из Telegram; утраченные при первой отправке детали не восстановятся |

Telegram [описывает сжатие обычных фото и режим HD](https://telegram.org/blog/direct-to-channel-trim-voice-and-more).
Для фото с iPhone важен способ отправки, а не модель телефона. Если нужен именно
оригинал, сначала получите неизменённый исходный файл, затем прикрепите его в Telegram
как файл из приложения «Файлы». При экспорте из «Фото» или передаче между приложениями
может происходить преобразование HEIC/HEIF в JPEG; такое преобразование бот отменить не может.
Apple описывает [получение оригиналов из iCloud](https://support.apple.com/111762)
и [особенности форматов HEIF/HEVC](https://support.apple.com/116944).

Файлы HEIC и DNG обрабатываются как документы: бот сохраняет полученное содержимое и
расширение без конвертации. Переданные в файле EXIF сохраняются вместе с остальными байтами.
Live Photo как отдельный тип сообщения пока не поддерживается; для архивации передавайте
исходные фото и видео отдельными документами.

Публичный Bot API [позволяет скачивать файлы до 20 МБ](https://core.telegram.org/bots/api#getfile).
Крупные ProRAW/DNG и видео могут превышать этот лимит и будут отклонены ботом.
Проверка JPEG с EXIF в тестах сравнивает байты и SHA-256 на входе скачивания и на входе
клиента Яндекс.Диска. Это проверка кода с подменой сети; реальную цепочку iPhone → Telegram →
Диск следует проверить на своём исходном файле, сравнив SHA-256 оригинала и скачанного с Диска файла.

## Возможности

- Асинхронное скачивание из Telegram и загрузка на Диск.
- Сохранение исходных имён и расширений документов и видео.
- Безопасные имена файлов с префиксом из ID чата, ID сообщения и идентификатора медиа.
- Ограничение размера файлов и количества одновременных передач.
- Временные файлы на диске с очисткой после успеха, ошибки или отмены.
- Создание папки назначения, включая родительские папки, при запуске.
- Повторы временных сетевых ошибок и понятные сообщения об отказах.
- Проверка настроек при запуске и маскирование токенов в журнале.

Все разрешённые пользователи сохраняют файлы в одну папку одного Яндекс.Диска.
Повторная обработка того же сообщения использует тот же путь и перезаписывает этот файл.
Отправка того же вложения новым сообщением создаёт отдельный файл.

## Требования

Для локального запуска: Python **3.12–3.14** и Poetry **2.5.1**.
Docker-образ использует Python **3.13**; для запуска контейнера достаточно Docker с Compose.

Нужны токен Telegram-бота от [BotFather](https://t.me/BotFather),
[OAuth-токен Яндекс.Диска](https://yandex.ru/dev/disk-api/doc/ru/concepts/quickstart#oauth)
с правами чтения и записи, а также числовые Telegram ID разрешённых пользователей.

## Настройка

Настройка одинакова для локального запуска и Docker. Сначала выполните все шаги
этого раздела, затем выберите один способ запуска. После скачивания проекта выполняйте
команды из его папки — той, где лежат `README.md`, `pyproject.toml` и `docker-compose.yml`.

1. **Скачайте проект и откройте его папку в терминале.**

   Если Git ещё не установлен, установите его с [официального сайта](https://git-scm.com/downloads).
   Откройте PowerShell в Windows или «Терминал» в Linux/macOS и выполните:

   ```sh
   git clone https://github.com/nsat1/cloud-saving-bot.git
   cd cloud-saving-bot
   ```

   Первая команда скачивает проект в папку `cloud-saving-bot`, вторая переходит в неё.
   Если проект уже скачан, откройте терминал в его папке; повторно скачивать его не нужно.

2. **Подготовьте токены и список пользователей.**

   Для `BOT_TOKEN` нужен токен вашего Telegram-бота: [BotFather](https://t.me/BotFather).
   Для `YANDEX_TOKEN` нужен OAuth-токен с правами чтения и записи файлов на Диске:
   [соответствующий раздел документации Яндекса](https://yandex.ru/dev/disk-api/doc/ru/concepts/quickstart#oauth).
   Для `ALLOWED_IDS` подготовьте числовой Telegram ID своего аккаунта и ID остальных
   пользователей, которым разрешено сохранять файлы. Здесь нужны числа, а не имена вида `@username`.

3. **Создайте файл настроек `.env`.**

   Windows PowerShell:

   ```powershell
   Copy-Item .env.example .env
   ```

   Linux/macOS:

   ```sh
   cp .env.example .env
   ```

   В папке проекта появится копия примера настроек с именем `.env`.
   Если `.env` уже существует и заполнен, пропустите копирование, чтобы не затереть свои настройки.

4. **Заполните обязательные значения в `.env` и сохраните файл.**

   Откройте `.env` в текстовом редакторе. Замените первые три строки своими значениями:

   ```dotenv
   BOT_TOKEN=123456789:your_real_telegram_token
   YANDEX_TOKEN=your_real_yandex_oauth_token
   ALLOWED_IDS=729831195,167234567
   ```

   Токены и ID выше — только примеры; их нельзя оставлять как рабочие значения.
   Если доступ нужен только вам, в `ALLOWED_IDS` укажите одно число.
   Если пользователей несколько, перечислите их ID через запятую, без запятой в конце.
   Это содержимое файла, а не команды для терминала.
   Сохраните файл в UTF-8 под именем `.env`, а не `.env.txt`.

5. **Проверьте папку сохранения и остальные настройки.**

   По умолчанию файлы попадут в `/bot_uploads` на Яндекс.Диске.
   Для другой папки измените строку, например:

   ```dotenv
   YANDEX_FOLDER=/archive/telegram
   ```

   Бот создаст эту папку и недостающие родительские папки при запуске.
   Остальные значения из `.env.example` можно оставить без изменений.
   Полный список параметров приведён в таблице ниже.

6. **Выберите способ запуска.**

   Перейдите к [запуску в Docker](#запуск-в-docker) или [локальному запуску](#локальный-запуск).
   Запускайте один экземпляр бота на один Telegram-токен: два одновременно работающих
   экземпляра будут мешать получению сообщений.

Не добавляйте `.env` в Git и не публикуйте его содержимое.
При локальном запуске уже заданные переменные окружения процесса имеют приоритет над `.env`.
Compose передаёт значения из `.env` внутрь контейнера.

### Параметры `.env`

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `BOT_TOKEN` | обязательно | Токен Telegram-бота |
| `YANDEX_TOKEN` | обязательно | OAuth-токен Яндекс.Диска |
| `ALLOWED_IDS` | обязательно | Положительные ID через запятую, без пустых элементов |
| `YANDEX_FOLDER` | `/bot_uploads` | Папка на Диске, например `/archive/telegram`; создаётся автоматически |
| `MAX_CONCURRENT_UPLOADS` | `2` | Число одновременных передач, от 1 до 16 |
| `MAX_FILE_SIZE_MB` | `20` | Предельный размер файла, от 1 до 20 МБ |
| `REQUEST_TIMEOUT` | `60` | Таймаут сетевого запроса в секундах, от 1 до 600 |
| `SHUTDOWN_TIMEOUT` | `30` | Время ожидания активных обработчиков при остановке, от 1 до 600 секунд |
| `DROP_PENDING_UPDATES` | `false` | При `true` удалить накопленные обновления Telegram перед запуском |
| `LOG_LEVEL` | `INFO` | `DEBUG`, `INFO`, `WARNING`, `ERROR` или `CRITICAL` |

`YANDEX_FOLDER` задаётся относительно корня Диска с разделителем `/`.
Пути с `.`, `..`, пустыми промежуточными компонентами, обратными слешами и префиксом
`disk:` не допускаются. Создавать папку вручную не требуется.

## Запуск в Docker

Этот способ запускает приложение в контейнере. Python и Poetry на вашем компьютере
для него устанавливать не требуется. Перед началом выполните раздел [«Настройка»](#настройка).

1. **Установите и запустите Docker.**

   Следуйте [официальной инструкции установки Docker](https://docs.docker.com/get-started/get-docker/).
   В Windows/macOS запустите Docker Desktop и дождитесь готовности движка.
   В Linux нужны работающий Docker Engine и плагин Docker Compose.
   Откройте терминал в папке проекта и проверьте:

   ```sh
   docker version
   docker compose version
   ```

   Первая команда должна показать сведения и о Client, и о Server,
   вторая — версию Compose. Если есть ошибка подключения к движку,
   сначала запустите Docker; если отказано в доступе, проверьте права по инструкции установки.

2. **Проверьте наличие настроек.**

   В текущей папке должны находиться `docker-compose.yml` и заполненный `.env`.
   Если `.env` отсутствует или содержит примеры токенов, вернитесь к разделу «Настройка».

3. **Соберите образ и запустите бота.**

   ```sh
   docker compose up -d --build
   ```

   При первом запуске Docker скачает образ Python и установит зависимости — это может занять
   несколько минут. Дождитесь завершения команды. Параметр `-d` запускает бота в фоне,
   поэтому терминал можно закрыть после проверки запуска.

4. **Проверьте состояние контейнера и журнал запуска.**

   ```sh
   docker compose ps
   docker compose logs -f telegram-bot
   ```

   Контейнер должен быть в состоянии `Up` или `running`.
   В журнале успешного запуска появится `Starting bot; destination folder is ready`,
   затем `Start polling` и сообщение о запуске polling вашего бота.
   Если контейнер перезапускается или журнал содержит ошибку настроек/доступа,
   проверьте `.env`, токены и соединение с интернетом.
   Для выхода из просмотра журнала нажмите **Ctrl+C** — бот продолжит работать.

5. **Проверьте сохранение файла.**

   Откройте в Telegram именно своего бота, чей токен указан в `.env`.
   С аккаунта, чей ID внесён в `ALLOWED_IDS`, отправьте `/start`, затем небольшой файл до 20 МБ.
   Дождитесь сообщения об успешном сохранении и проверьте файл в папке `YANDEX_FOLDER`
   на своём Яндекс.Диске. Если бот совсем не отвечает, проверьте ID отправителя в `ALLOWED_IDS`:
   сообщения других пользователей он игнорирует.

6. **Остановите бота, когда это потребуется.**

   ```sh
   docker compose down
   ```

   Команда остановит и удалит контейнер; сохранённые файлы на Яндекс.Диске останутся.
   Для следующего запуска из той же папки выполните `docker compose up -d --build`.

7. **Примените изменения настроек или кода.**

   После редактирования и сохранения `.env` пересоздайте контейнер:

   ```sh
   docker compose up -d --force-recreate
   ```

   После обновления кода заново соберите образ и запустите контейнер:

   ```sh
   docker compose up -d --build
   ```

   Затем снова проверьте журнал, как в шаге 4.

Контейнер работает от непривилегированного пользователя; `.env` не включается в образ.
Период остановки контейнера — 45 секунд. Если увеличиваете `SHUTDOWN_TIMEOUT`,
увеличьте `stop_grace_period` в `docker-compose.yml`, чтобы он был больше времени
ожидания приложения.

## Локальный запуск

При этом способе бот работает как процесс на вашем компьютере. Перед началом выполните
раздел [«Настройка»](#настройка). Во время работы бота компьютер должен быть включён
и подключён к интернету, а терминал с запущенным приложением должен оставаться открытым.

1. **Установите Python и проверьте версию.**

   Проект поддерживает Python 3.12–3.14. В этих шагах используется **Python 3.13**;
   установите его с [официального сайта Python](https://www.python.org/downloads/).
   В Windows при установке включите Python Launcher, если установщик предлагает эту опцию.
   Откройте новый терминал и выполните команду для своей системы.

   Windows PowerShell:

   ```powershell
   py -3.13 --version
   ```

   Linux/macOS:

   ```sh
   python3.13 --version
   ```

   Ожидаемый результат — `Python 3.13.x`. Если команда не найдена, проверьте установку
   Python и откройте терминал заново. Если уже установлен Python 3.12 или 3.14,
   можно использовать его, заменив `3.13` на свою версию во всех командах этого раздела.

2. **Установите Poetry 2.5.1.**

   Команды ниже используют [официальный установщик Poetry](https://python-poetry.org/docs/#installation).
   Он создаст для Poetry отдельное окружение. Если `poetry --version` уже показывает
   `Poetry (version 2.5.1)`, повторная установка не нужна.

   Windows PowerShell:

   ```powershell
   (Invoke-WebRequest -Uri https://install.python-poetry.org -UseBasicParsing).Content | py -3.13 - --version 2.5.1
   $env:Path += ";$env:APPDATA\Python\Scripts"
   poetry --version
   ```

   Linux/macOS:

   ```sh
   curl -sSL https://install.python-poetry.org | python3.13 - --version 2.5.1
   export PATH="$HOME/.local/bin:$PATH"
   poetry --version
   ```

   Ожидаемый результат последней команды — `Poetry (version 2.5.1)`.
   Строка с `Path`/`PATH` делает Poetry доступным в текущем терминале.
   Чтобы команда работала и в новых терминалах, добавьте указанный каталог в PATH
   своей системы по инструкции установщика. Если Poetry установлен другим способом,
   используйте каталог, который сообщил тот установщик.

3. **Откройте папку проекта и выберите Python для приложения.**

   Вернитесь в папку `cloud-saving-bot`, скачанную на этапе настройки.
   Убедитесь, что в ней лежат `pyproject.toml` и заполненный `.env`, затем выполните:

   ```sh
   poetry env use 3.13
   ```

   Poetry выберет Python 3.13 и создаст виртуальное окружение для зависимостей проекта.
   Если эта версия не найдена, вернитесь к проверке Python в шаге 1.

4. **Установите зависимости приложения.**

   ```sh
   poetry install --only main --no-root
   ```

   Дождитесь успешного завершения установки. Poetry установит версии библиотек
   из `poetry.lock` в окружение проекта; инструменты для тестов в этом способе запуска не нужны.

5. **Запустите бота.**

   ```sh
   poetry run python -m app.main
   ```

   Приложение проверит настройки и доступ к Диску, создаст папку назначения
   и начнёт получать сообщения из Telegram.
   В терминале появится `Starting bot; destination folder is ready`, затем `Start polling`
   и сообщение о запуске polling вашего бота. Команда продолжит работать — это нормально.
   Если приложение завершилось с ошибкой, прочитайте сообщение в терминале:
   проверьте указанный параметр `.env`, доступ к Диску или соединение с интернетом.

6. **Проверьте сохранение файла.**

   Откройте своего бота в Telegram с аккаунта, чей ID указан в `ALLOWED_IDS`.
   Отправьте `/start`, затем небольшой файл до 20 МБ. Дождитесь сообщения об успешном
   сохранении и найдите файл в папке `YANDEX_FOLDER` на своём Яндекс.Диске.
   Если ответа нет, проверьте ID отправителя: доступ разрешён только пользователям из `ALLOWED_IDS`.

7. **Остановите или перезапустите бота.**

   Для остановки нажмите **Ctrl+C** в терминале с приложением и дождитесь завершения процесса.
   После изменения `.env` сначала остановите бота, сохраните настройки,
   затем снова выполните `poetry run python -m app.main` из папки проекта.

## Версии, сборки и обновление

Номер версии приложения записан в `pyproject.toml`. Изменения и особенности перехода
с предыдущей версии описаны в [CHANGELOG.md](CHANGELOG.md).
[Релизы на GitHub](https://github.com/nsat1/cloud-saving-bot/releases) содержат исходники
и готовый Docker-образ для Linux/amd64 с контрольной суммой SHA-256.

### Обновление с v1.0.0 до v1.1.0

1. **Остановите работающий экземпляр бота.**

   Для Docker Compose выполните `docker compose down` из папки старого проекта.
   Для локального запуска нажмите Ctrl+C в терминале с ботом.

2. **Сохраните свой `.env`.**

   Оставьте файл настроек в папке проекта или сделайте его копию в отдельной папке.
   При обновлении используйте свои токены и ID; не заменяйте их примерами из `.env.example`.

3. **Получите исходники новой версии.**

   Если проект был скачан через Git, выполните в его папке:

   ```sh
   git fetch --tags origin
   git switch --detach v1.1.0
   ```

   Если вы скачивали ZIP, загрузите `Source code (zip)` со страницы релиза `v1.1.0`,
   распакуйте в новую папку и перенесите в неё свой `.env`.

4. **Проверьте требования новой версии.**

   Для локального запуска нужны Python 3.12–3.14 и Poetry 2.5.1.
   Docker установит нужный Python при сборке образа. Новые необязательные параметры `.env`
   можно не добавлять — приложение использует значения по умолчанию.

5. **Соберите и запустите обновлённого бота.**

   Для Docker Compose:

   ```sh
   docker compose up -d --build
   docker compose logs -f telegram-bot
   ```

   Для локального запуска:

   ```sh
   poetry env use 3.13
   poetry install --only main --no-root
   poetry run python -m app.main
   ```

   Если используете Python 3.12 или 3.14, укажите эту версию в `poetry env use`.
   Проверьте работу, отправив боту небольшой файл. Ранее сохранённые файлы на Диске останутся.

### Запуск готового Docker-образа из релиза

Для компьютера с Linux-контейнерами и архитектурой amd64 скачайте из релиза файл
`cloud-saving-bot-v1.1.0-linux-amd64.tar.gz`. Откройте терминал в папке с этим архивом
и заполненным `.env`, затем выполните:

```sh
docker load --input cloud-saving-bot-v1.1.0-linux-amd64.tar.gz
docker run -d --name cloud-saving-bot --env-file .env --init --restart unless-stopped --stop-timeout 45 cloud-saving-bot:v1.1.0
docker logs -f cloud-saving-bot
```

Перед этим остановите предыдущий экземпляр бота. Для остановки этого контейнера
выполните `docker stop cloud-saving-bot`; для повторного запуска — `docker start cloud-saving-bot`.
При изменении `.env` контейнер нужно остановить, удалить командой `docker rm cloud-saving-bot`
и создать заново командой `docker run` выше. Файлы на Яндекс.Диске при этом сохраняются.
Для других архитектур используйте сборку из исходников через Docker Compose.

## Ограничения и восстановление

Стандартный облачный [Telegram Bot API](https://core.telegram.org/bots/api#getfile)
позволяет скачивать файлы размером до 20 МБ. Бот использует этот API.
В настройках приложения МБ рассчитываются как 1024 × 1024 байта;
если Telegram отклоняет файл своим лимитом, бот также сообщает об ошибке размера.

Передача занимает один слот от начала скачивания до конца загрузки на Диск.
Число одновременно обрабатываемых сообщений ограничено значением
`MAX_CONCURRENT_UPLOADS × 4`. Обработчики, ожидающие свободный слот,
не скачивают файл заранее.

Скачивание повторяется до трёх попыток при временной сетевой ошибке.
Короткие ограничения частоты Telegram ожидаются до пяти секунд за попытку;
длительные ограничения возвращают ошибку пользователю.
SDK Диска выполняет до двух повторов сетевых запросов после первой попытки.
Ошибки доступа и нехватка места сообщаются пользователю.

По умолчанию накопленные обновления при запуске сохраняются.
При обычной остановке бот ждёт активные обработчики до `SHUTDOWN_TIMEOUT`,
затем отменяет незавершённые операции и закрывает сетевые сессии.

Telegram хранит необработанные обновления ограниченное время.
Незавершённая передача при аварийном завершении процесса или превышении времени остановки
может потребовать повторной отправки: очередь задач не сохраняется на диске.
Успешная загрузка и доставка ответного сообщения также являются отдельными операциями;
файл может быть сохранён даже при недоставленном подтверждении.

После успешной передачи временный файл удаляется. При принудительном завершении
процесса средствами ОС временные файлы могут остаться в системном каталоге.
Выделите свободное место для параллельных загрузок.

Файлы, ранее сохранённые старой версией бота под `file_id`, автоматически не переименовываются.
Новый формат имён применяется к новым передачам.

## Структура проекта

```text
app/
  main.py                   # создание зависимостей, запуск и остановка
  config.py                 # загрузка и валидация Settings
  logging_config.py         # журналирование и маскирование токенов
  media.py                  # метаданные медиа и безопасные имена
  handlers/
    __init__.py             # фабрика маршрутизатора
    start.py                # команда /start
    media.py                # общий обработчик фото, видео и документов
    other.py                # подсказка для остальных сообщений
  middlewares/
    access.py               # контроль разрешённых пользователей
    lifecycle.py            # ожидание активных обработчиков при остановке
  services/
    file_transfer.py        # скачивание, лимиты и временные файлы
    yandex_disk.py          # асинхронный адаптер Диска и ошибки API
tests/                      # проверки без рабочих токенов и внешних запросов
.github/workflows/ci.yml     # Python 3.12–3.14 и проверка Docker-образа
```

Импорт модулей не читает переменные окружения и не создаёт клиентов.
Настройки и сервисы создаются при запуске и передаются обработчикам через Dispatcher.

## Разработка и проверки

Установка с инструментами разработки:

```sh
poetry install --no-root
poetry check --lock --strict
poetry run ruff check app tests
poetry run ruff format --check app tests
poetry run pytest -q
```

Тесты написаны для **pytest**; асинхронные сценарии запускает `pytest-asyncio`,
а покрытие измеряет [`pytest-cov`](https://pytest-cov.readthedocs.io/en/latest/).
`unittest.mock` используется только для подмены зависимостей и проверки вызовов.
Тесты подменяют сетевые операции Telegram и Яндекс.Диска и не используют настоящие токены.
Проверяются маршрутизация, доступ, безопасные имена, ограничения размера,
повторы, параллелизм, очистка файлов и завершение обработчиков.

### Покрытие тестами

Из корня проекта выполните:

```sh
poetry run pytest -q --cov=app --cov-report=term-missing --cov-report=xml --cov-report=html
```

Команда запускает тесты, показывает непокрытые строки и ветвления в терминале,
создаёт `coverage.xml` и интерактивный HTML-отчёт `htmlcov/index.html`.
Измеряется весь пакет `app`, включая модули, которые тесты не импортировали;
файлы тестов в процент покрытия приложения не входят.
Конфигурация в `pyproject.toml` включает измерение ветвлений и минимальное общее
покрытие **90%**: при меньшем результате команда завершится с ошибкой.
Отчёты не добавляются в Git и не передаются в контекст сборки Docker.

Замер **2 октября 2026 года** на Windows, Python 3.12.14: **89 тестов успешно**.

| Метрика | Проверено | Покрытие |
| --- | --- | --- |
| Исполняемые строки | 340 из 369 | 92,14% |
| Ветвления | 59 из 66 | 89,39% |
| Общее покрытие строк и ветвлений | 399 из 435 | **91,72%** |

Это снимок текущего результата; актуальные значения показывает новый запуск тестов.
Покрытие показывает выполнение кода в тестах и не подтверждает работу внешних сервисов.
Часть путей ошибок запуска, журналирования и ответов пользователю пока не покрыта.
Реальные запросы к Telegram и Яндекс.Диску, а также пересылка с iPhone проверяются отдельно.

CI запускает pytest с измерением покрытия на Python 3.12, 3.13 и 3.14,
сохраняет XML/HTML-отчёты в артефактах `coverage-python-<версия>` на 14 дней,
затем собирает Docker-образ и проверяет импорт приложения и запуск от
непривилегированного пользователя. Отчёты доступны на странице запуска GitHub Actions;
они сохраняются также при падении тестов, если успели сформироваться.

После изменения зависимостей обновите lock-файл и повторите проверки:

```sh
poetry lock
poetry install --no-root
```

Для обновления всех разрешённых версий зависимостей используйте `poetry update`.
Прямые зависимости задаются в `pyproject.toml`, точные версии и хеши — в `poetry.lock`.
